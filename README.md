# When Does Relational Structure Pay Off?

**Accuracy–cost tradeoffs of relational graph models for clinical trial outcome prediction.**
Stanford CS224W course project, Manel Bermad.

[![tests](https://github.com/mbermad/relational-trials/actions/workflows/ci.yml/badge.svg)](https://github.com/mbermad/relational-trials/actions/workflows/ci.yml)
[![Open in Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/mbermad/relational-trials/blob/main/notebooks/milestone_colab.ipynb)

Clinical trials are linked to sponsors, conditions, interventions and sites that thousands of
other trials share. This project asks when learning directly on that relational structure
(graph neural networks over the database) beats strong tabular baselines, what it costs, and
what the models learn. Data: [RelBench](https://github.com/stanford-star/relbench)'s
`rel-trial` database, built from ClinicalTrials.gov.

| Task | Question | Metric |
|---|---|---|
| `study-outcome` | Will the trial meet its primary endpoint? | AUROC (higher is better) |
| `study-adverse` | How many patients will have serious adverse events or die? | NMAE = MAE / train std (lower is better); MAE also reported |

## Quickstart

**Colab (recommended, GPU):** open `notebooks/milestone_colab.ipynb` with the badge above and
run all cells.

**Local:**

```bash
git clone https://github.com/mbermad/relational-trials.git && cd relational-trials
pip install -e ".[dev]"                     # data, LightGBM, evaluation, tests
pip install -e ".[gnn]"                     # + PyTorch Geometric, PyTorch Frame
pip install pyg-lib -f https://data.pyg.org/whl/torch-${TORCH}+${CUDA}.html  # e.g. torch-2.8.0+cu126

python scripts/run.py explore               # schema, label stats, figures
python scripts/run.py lgbm                  # both LightGBM variants, both tasks, 3 seeds
python scripts/run.py rdl --text glove      # hetero GraphSAGE, both tasks, 3 seeds
python scripts/run.py tables                # results table (Markdown + LaTeX)
pytest -q                                   # unit + end-to-end tests on synthetic data
```

Every command accepts `--tasks`, `--seeds` and `--results`; `python scripts/run.py -h` lists
all options. `--dataset path/to/folder` runs on a local copy (the tests use a synthetic one).

## Design

```
src/reltrial/
  data.py       load a RelBench task + train/val/test tables (test labels for offline eval)
  features.py   leakage-safe tabular + relational aggregate features
  lgbm.py       LightGBM: fixed random-search budget on val, then several seeds
  rdl.py        relational entity graph + hetero GraphSAGE (adapted from RelBench)
  evaluate.py   metrics, run records, CIs, paired bootstrap
  explore.py    schema summary, label statistics, figures
  tables.py     results tables (Markdown, LaTeX)
scripts/run.py  one command per result
tests/          leakage tests, metric tests, end-to-end runs on synthetic data
notebooks/      Colab notebook reproducing the milestone
```

**Leakage rules.** A prediction for a trial at seed time *t* may only use (1) database rows
dated ≤ *t*, the rule RelBench's temporal neighbor sampler applies to the GNN, and (2) other
trials' labels once they are known, i.e. label time + the task's 1-year window ≤ *t*.
`tests/test_features.py` checks both on hand-built examples.

**Fair comparison.** All models share the same splits, metrics, seeds (0, 1, 2) and logging.
LightGBM variants get the same tuning budget (20 trials); the GNN uses RelBench's reference
hyperparameters. Every run writes `results/runs/<task>/<model>/seed<k>.json` with metrics,
training time, inference latency and peak GPU memory.
